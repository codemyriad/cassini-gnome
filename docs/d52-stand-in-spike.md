# R67 transport-adoption spike — DO NOT MERGE

This WIP branches from GNOME #143 at c4d9c50. It is not part of #143.
The happy path works with the existing protocol: bind a new browser token to
an active stand-in by unique callGeneration, retain its app capture key, folder
and microphone, translate the transport origin, canonicalize control status and
send Stop with the wire token. A real control/audio RPC regression passes.
The reader/ownership implementation is independently committed on #143.

The spike is unsafe to ship. Run:

    PYTHONPATH=src python3 -m pytest -q tests/test_browser_capture.py::test_r67_late_transport_after_stop_cannot_create_a_second_recording

That event-synchronized real-broker test FAILS (expected rejection, got Started):
1. Browser Start is rejected, so the broker starts a system-sound stand-in F.
2. A fresh browser Start is pending, with a token X generated by the extension.
3. The user stops F before the native host receives X's Start. F finishes.
4. Stop names F. The extension cannot cancel X with that token:
   background.js cancelPendingStart returns when the session token differs.
5. The delayed X Start arrives, has the same callGeneration, and creates a new
   recording because F has already finished. A generation identifies a call,
   not the recording operation that was cancelled.

Refusing every later Start for that generation would also refuse an explicit
new Record for the same call. Timestamps are not a reliable operation identity.
Earlier control status can additionally expose X before native binding exists.
A broker-only alias is therefore not a sufficient shared cancellation contract.

Proposed shared opt-in (for coordinator/Mac decision before implementation):
- Advertise resume-capture-v1 and add an optional Start resume target containing
  the existing captureId F and timelineOriginMs. Require independent mode and
  the selected callGeneration. Desktop sends it only when the capability exists.
- Extension uses F and its original origin for the session and native Start,
  including early status and scoped Stop. It does not invent a second token X.
- Native broker resumes only the active eligible stand-in; a stopped or changed
  target is rejected. Native acknowledgement confirms support before capture.
- Keep normal fresh Start unchanged. Bump extension version for local updates.
- Shared vectors: both status/native-start orders, Stop before native Start,
  Stop before session construction, a new manual Record after Stop, stale A/B,
  mic/selection preservation, and D49 half-open seam. Mac implements the twin.

No protocol, shared schema or catalog changes are made by this branch. The
known failing regression is deliberately retained; this is evidence, not a
relaxed gate. Tests use private Docker/audio and no desktop devices.
