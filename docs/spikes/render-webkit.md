**WebKit transcript rendering spike — 2026-11-10 — do not merge**

Verdict: **only as fallback, pending native-input certification**. This spike is **not a passing native-kinetic acceptance result**. A fully laid-out DOM removes the unrealized-row height estimates that cause the GtkListView origin to move. The prototype preserves the viewer's reading structure, but adds a browser engine, its child processes, a second theme/focus/accessibility surface, and substantial memory/dependency cost. Prefer an adequately performing native solution if the other spikes establish one. This is a Library Meeting page prototype; the standalone reader is unchanged.

Enable with `CASSINI_TRANSCRIPT_RENDER=webkit`; WebKitGTK's `WebKit` GI namespace version `6.0` must be installed. No WebKit import occurs on the default path. `CASSINI_TRANSCRIPT_WEBKIT_PLAIN=1` is the benchmark's no-header presentation for the undiarized fixture.

The renderer uses `article` → speaker/timestamp header → one paragraph, inline interjection spans, and a button per stored word, following gocassini's `MeetingView.svelte` and `TranscriptWords.svelte`. It consumes the existing `reading_turns` / `join_items` projection rather than implementing turn detection in JavaScript. It does not use `content-visibility`, row virtualization, custom scroll physics, or height estimates. WebKit owns its native scroll surface; nesting it inside a GtkScrolledWindow would create competing scroll surfaces. GTK's own scrolling behavior is untouched.

Working in the spike: every displayed word, including each chip word, seeks through a validated timestamp bridge; timestamps seek; current-word highlight updates through one bounded in-flight IPC; follow keeps the sounding word visible and yields to wheel/touch/keyboard/scrollbar interaction; speaker-listening row decoration and explicit row navigation use the bridge. The GTK speakers sidebar remains the existing implementation. Highlight updates toggle only entering/leaving word classes; forward playback searches sorted word start/end indices, without rebuilding paragraph markup. Search marks/jumps exist as a JavaScript method but have no new GTK search UI.

The measured environment was GTK 4.22.2, Adwaita 1.9.0, WebKitGTK 2.52.0, GStreamer 1.28.2, Python 3.14.4 and GNOME Shell 50.1, using Cairo/software rendering. One active WebProcess remained per meeting after page-close cleanup; the 4-hour run plus its private desktop stayed below the 2.5 GB budget. Evidence is in `tests/ui/results/webkit/` (summaries, compressed frame traces, PNG paint snapshots, native-input diagnostics, versions and AT-SPI output).

All inputs are synthetic English and finished portable Opus meetings: PR #310's generator, scaled to approximately 12k/50k words, two speakers, uneven paragraphs, overlaps, and folded interjections. The undiarized hour assigns one logical timing owner and hides speaker/time headers; this preserves every word atom, including originally simultaneous atoms, but changes reading-row grouping. No real recording was read or copied.

The harness is adapted from PR #310 (`45b8bb8`) and its `transcript_measurements.py` approach: GTK frame-clock callbacks plus thread CPU timing, with DOM anchor observations on the WebProcess frame clock. A continuous GTK tick keeps load gaps meaningful instead of counting idle time; fixture generation and model decoding finish before the open interval. That PR's label measurement tests apply to its Pango subclass, not to WebKit.

Native attempts inject `ScrollSource.FINGER` through Mutter's virtual pointer, verify the compositor's pointer position, and send axis-stop events. They did not reliably produce content motion on fresh headless desktops. Emitting the WebView's native controller signals without a current GDK event also failed. Stationary zero-reversal observations are deliberately rejected; the native mode returns exit code 2 when certification fails. A physical touchpad or a verified Wayland input driver is still required to close this acceptance gap.

The separately labelled `dom-smooth` audit applies PR #310's pixel steps (75, 138, 225, 213, 163), then asks the browser to animate another 3000 px through its own `scrollBy({behavior:'smooth'})`. This is a geometry/frame-cost check, **not a simulation of native touchpad kinetic physics**. It runs six alternating down/up sequences in each of paused and running/follow-disabled modes, and observes motion until twelve unchanged browser frame samples. Test-only repositioning happens outside reversal scoring, away from boundaries. Resize waits for actual GTK allocations and three stable browser width/extent samples at each of two sizes, rather than guessing a delay.

`upper` is `document.documentElement.scrollHeight`, the browser's scroll extent; there is no GTK adjustment for this surface. An anchor sample records the first visible article and its pixel offset; reversal scoring checks both the article/offset and `scrollY`. A resize is expected to change the extent, and is measured separately. First paint is a conservative upper bound: completion of a real WebKit viewport snapshot plus a GTK paint, saved as PNG. Layout-ready time waits for two browser animation frames and subsequent GTK paints. Exact first-contentful-paint latency is not claimed. Worst frame intervals include scheduling/compositor delays on the shared software-rendered host; GTK CPU time does not include child-process CPU. JavaScript highlight timings are quantized to 1 ms; the mean is useful across many updates, individual zeroes are below resolution. IPC submission CPU excludes async WebProcess work. RSS sums the app and descendants, double-counting shared pages; it is not incremental browser-only memory or PSS. The private compositor is additional to that figure.

**Offline behavior.** The document, CSS, and JavaScript are application-owned local files; all meeting/speaker text is HTML-escaped, with no external URLs, images, web fonts, CDNs, or libraries. CSP denies connections, images, fonts, media, frames, objects, forms, and base URLs; only bundled inline script/style is allowed. The view uses an ephemeral NetworkSession, disables page/local-storage/database caching, DNS prefetch, media/WebRTC/WebGL, denies permission requests, cancels downloads, and rejects navigation/new windows except the application document's `about:blank`. The private QA desktop has no network namespace connectivity. The live test deliberately attempts a fetch and image load and observes the corresponding `connect-src` and `img-src` violations. This demonstrates renderer requests are blocked, not just that an unavailable server failed. The default application sandbox remains enabled; this spike does not disable WebKit's process sandbox. Production should add a network-syscall regression gate and retain these policies if future features add URL-bearing markup.

**Accessibility, selection, growth, and gaps.** The native AT-SPI probe found a `document web`, the Transcript landmark, article/header/paragraph nodes, and a word button named `1. — seek to 0:00, Alice` with one exposed action. This confirms the bridge reaches the real accessibility tree; it is not an Orca usability or full-tree performance certification.

Word buttons carry accessible names containing the stored word, timestamp, and speaker; standard browser button activation supplies keyboard seeking. Paragraphs and chips contain real text nodes, including the chip's `(Name: words)` copy text. The live harness selects a word through the DOM and verifies WebKit's native Copy command publishes that exact text on the private desktop clipboard. Mouse-drag selection across inline buttons and chips, Orca reading order, zoom/high contrast, bidi text, and focus return between GTK and the web document still need a full interaction audit. There are up to 50k button tab stops; a production keyboard-navigation design is needed. The existing GTK Shift+Return row shortcut and transcript-name-to-listening action are not wired into the DOM, and native header auto-tags/color provenance styling is incomplete. CSS uses system Cantarell at fixed sizes rather than deriving all GTK font/accent/high-contrast settings. The document language currently assumes English.

Live updates have a prototype prefix diff: retain unchanged articles, remove/rebuild the changed tail, and reindex word timings. It retains prefix DOM nodes; end-to-end recording growth and selection anchoring were not exercised. Reindexing remains O(words), and a changed paragraph above the viewport can still change layout. Production must anchor the visible word across such edits and preserve search/listening state. Renaming speakers currently reloads the document and loses selection/scroll state; incremental header/chip updates are needed. Search handles a per-word substring and first-hit jump; production should use the existing cross-word match model and stable original word IDs, with focused-match stepping and queued navigation until the document is ready. It must avoid replacing text nodes inside an active selection. Browser-native find alone would not supply Cassini's transcript/search navigation semantics.

**Packaging cost.** The experimental flag deliberately does not add a mandatory dependency to existing packages. A production switch would need these manifest changes:

| Distribution | Runtime dependency | Cost / work |
| --- | --- | --- |
| Debian/Ubuntu | `gir1.2-webkit-6.0` (pulls `libwebkitgtk-6.0-4`, JavaScriptCore and its GI data) | In the measured Ubuntu 26.04 package set, these four packages alone download 31.7 MiB and install 122.4 MiB, before missing transitive dependencies. |
| Fedora RPM | `webkitgtk6.0` (includes `WebKit-6.0.typelib`, pulls `javascriptcoregtk6.0`) | Add the Python GI runtime dependency explicitly; Python loading does not produce an ELF auto-requirement for the app. Separate WebProcess, NetworkProcess, sandbox helpers and engine updates become part of support. |
| Arch | `webkitgtk-6.0` | Official package listing: 38.5 MB compressed / 138.6 MB installed for WebKit alone; transitive/shared dependency state changes the actual incremental cost. |

The Ubuntu measurement used WebKit/JavaScriptCore `2.52.0-1`, `dpkg-deb -f ... Installed-Size` and archive byte sizes. It is not a claim about current security-update versions. The engine itself is roughly 89 MiB of the measured installed WebKit library. Optional media features being disabled does not remove their package dependencies. No package/container builds were run. openSUSE's typelib/runtime naming needs a distribution check before editing its RPM branch; Flatpak requires verification of WebKit GI/runtime availability and nested sandbox support for every shipped runtime rather than assuming GNOME Platform contains it.
