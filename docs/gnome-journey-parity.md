# D37 GNOME journeys

The recording introduction is “Before you record”. It repeats until Don't show again is selected. “Allowed” means this app session has actually received and recorded native microphone/system PCM; on Linux the capture path is PulseAudio, so there is no speculative permission prompt or device probe on opening this sheet. Browser remote audio alone never marks the system-sound permission allowed. The broker reports native PCM evidence privately to its app; no extension protocol changes.

No supported installed browser is a neutral state in Settings and setup, with Add disabled. Before the first real companion handshake the Library has no browser state/promotion; setup lives in Settings and the Meeting card. A GSettings flag retains the first-connection history across launches. After a past connection, an unavailable companion can show a Library line with its action; no-browser hides it again. Step 2 is hidden until step 1 has actually connected once. First-step failures retain a retry action. Browser discovery and per-user registration already use installed executables and create missing NativeMessagingHosts folders, so the browser need not have been opened. Add already launches the chosen supported executable directly, regardless of the desktop's default browser.

Sub-MB sizes now use shared KB copy with the existing binary-unit, half-up rule. The updated catalog is copied verbatim from coordination95f1e68; the promised extra KB vector is requested in REPLIES R37, and existing shared vectors remain unchanged. Local boundary tests cover KB/MB transitions. Clock times use the locale's short 12/24-hour style; durations retain their fixed elapsed-time format. The launcher initialises the environment's locale while retaining `runtime.check()`.

Stopping through the global shortcut while another app has focus posts “Recording saved: {title}” after finalisation, once per captured meeting. The title is read off GTK from saved metadata, so edits are honoured. There is no success notification for a missing/empty capture or an unsuccessful read. Its short metadata read holds the app until notification delivery; it never cancels writing down.

Return and double-click open a meeting; a single click selects its preview. The audio-only Meeting page retains playback, Write it down, Export and Rename. A writing-down preview now includes the row's exact state/estimate and refreshes when ETA changes.

Validation: backend tests, real locale subprocesses (en_GB/en_US in the UX job), the existing private companion/Flatpak-gate journeys, and `tests/ui/journey-parity.py`. That test uses native Return/mouse input, real synthetic GStreamer input and private portal/notification wire services; any Gtk-WARNING/CRITICAL or callback exception fails it. It produces a 1120×720 `journey-parity.png` in `ux-boards`. No host desktop or audio is involved.
